# Code Review

## Шаги

1. **Определи изменения**
   - База — `claude/pensive-brown-28588t` (`main` в этом репозитории пустой):
     `git diff origin/claude/pensive-brown-28588t...HEAD --stat`
   - Если ветки нет локально — `git fetch --depth=50 origin claude/pensive-brown-28588t`
   - Прочитай полный дифф

2. **Проверь каждый файл**
   - **Корректность**: логика, граничные случаи, часовые пояса (даты с поясом в параметрах API), обработка ошибок
   - **Безопасность**: Fernet для RTSP-учёток, JWT, bcrypt, валидация ввода, матрица прав §18, токены не попадают в логи, журнал аудита
   - **Производительность**: N+1 запросы, блокировка event loop, утечки памяти, блокировка слоя записи
   - **Схема БД**: изменение модели сопровождается идемпотентной миграцией в `apply_schema_migrations()`; допустимо падающие операторы — в `begin_nested()`
   - **Стиль**: type hints, комментарии на русском со ссылкой на `§N`, без массового переформатирования
   - **Архитектура**: независимость слоёв записи и аналитики, remux без декодирования

3. **Тесты**
   - Есть ли тест на изменённое поведение и проверяет ли он **контракт ТЗ**, а не текущую реализацию
   - Не уйдёт ли новый тест в `skip` в CI (нет Postgres/ffmpeg/pg_dump)
   - Порог покрытия backend — 77 %

4. **Объём (режим MVP, см. CLAUDE.md)**
   - Изменение чинит пункт MVP или красный CI, а не добавляет новую функцию
   - Нет попутного рефакторинга и посторонних файлов; новые отчёты/аудиты вместо исправления — 🟡

5. **Документация** — `docs/API_DOCS.md`, `docs/USER_GUIDE.md`, `docs/CHANGELOG.md`
