# Оптимизация производительности

Правило ТЗ (§22): переписывать ради скорости можно, но **только с бенчмарком до и после**.

## Шаги

1. **Измерь до изменений**
   - Подходящий бенчмарк из `perf/bench_*.py` (remux, live_latency, scaling, ram_scaling, archive_index, recovery, ...)
   - Нагрузка — `loadtest/`
   - `docker stats` для CPU/RAM по сервисам; `GET /api/system/metrics`
   - Зафиксируй цифры: FPS детекции на канал, задержку live, CPU на камеру записи

2. **Слой записи** (`worker/record_layer.py`, MediaMTX)
   - Только remux, CPU ≤ 0.04 ядра/камера (§19)
   - Восстановление потока ≤ 5 с, 0 пропущенных сегментов
   - Задачи очистки/индексации не должны блокировать запись (см. `worker/tests/test_cleanup_does_not_block_record_layer.py`)

3. **Слой аналитики** (`worker/worker.py`, `analytics_source.py`, `model_loader.py`)
   - ONNX Runtime: провайдер (`hwaccel.py`) и число потоков (`ort_threads.py`)
   - Привязка к ядрам/NUMA — `cpu_affinity.py` (2× Xeon, §17)
   - Префильтр движения, пропуск кадров, `idle_fps` после 20 с без движения
   - Субпоток для детекции, если он ≥ 640×480
   - Загрузка модели не должна блокировать запись (`test_model_load_does_not_block_record_layer.py`)

4. **БД** (pgvector)
   - HNSW-индексы на эмбеддингах; `EXPLAIN ANALYZE` для тяжёлых запросов
   - Поиск по архиву ≤ 5 с на 500 000 сегментов (§7), по фото ≤ 3–5 с на 100 000 лиц (§15)

5. **Upscaler** (`upscaler/upscaler.py`)
   - Длина очереди: `redis-cli LLEN upscale:queue`
   - Пониженный приоритет процесса, OpenCV-fallback при сбое GFPGAN
   - Апскейл не должен влиять на скорость live-детекции

6. **Измерь после** на всех трёх профилях и приложи цифры к коммиту/PR

## Профили (SPEC §15, таблица в README)
- **Экономный**: 5 FPS, каждый 4-й кадр, префильтр, buffalo_s, 640 px
- **Стандартный**: 10 FPS, префильтр, buffalo_s
- **Максимальный**: 15 FPS, без префильтра, buffalo_l, полный апскейл

## Чек-лист
- [ ] Есть цифры до и после
- [ ] Запись — remux без декодирования
- [ ] Аналитика не тормозит запись, и наоборот
- [ ] Префильтр движения работает (кроме Максимального)
- [ ] Адаптивный FPS (`idle_fps`) работает
- [ ] CPU ≤ 80 %, RAM ≤ 80 % при полной нагрузке (§19)
- [ ] Redis pub/sub не блокируется
