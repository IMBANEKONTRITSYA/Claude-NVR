# FaceWatch — масштабируемая система видеонаблюдения
## Версия: Production NVR Edition

## 1. Вводные

**FaceWatch** — это промышленная система видеонаблюдения уровня NVR (Network Video Recorder) с встроенным модулем распознавания лиц как уникальным конкурентным преимуществом.

### Масштабируемость
- **Количество камер:** от 12 до 250+ (конфигурируется)
- **Камеры аналитики:** от 0 до N (конфигурируется, зависит от возможностей сервера)
- **Принцип:** архитектура не привязана к конкретным числам — все параметры настраиваются под объект

### Конфигурация камер (типичная)
- **Основной поток:** высокое качество для записи и live-просмотра (H.265, 720p-2K, 15-30 fps)
- **Субпоток:** низкое качество для детекции движения (H.265, CIF-D1, 10-15 fps)
- Камера может иметь один или два потока в зависимости от модели

### Принцип разделения (архитектурный)
- **Слой записи:** все камеры пишутся без декодирования (remux)
- **Слой аналитики:** только выбранные камеры обрабатываются нейросетями
- Слои независимы: отказ аналитики не влияет на запись, и наоборот

### Развёртывание
- Docker Compose, запуск одной командой
- Поддержка Windows 10/11 Pro и Linux-серверов
- Автоматическое определение оптимальных параметров под железо

## 2. Архитектура: три независимых слоя

```
┌────────────────────────────────────────────────────────┐
│ СЛОЙ ЗАПИСИ (Recording Layer)                          │
│ MediaMTX (один процесс):                               │
│  - тянет основные потоки всех камер (1 pull/камера)    │
│  - пишет remux-сегменты на диск БЕЗ декодирования      │
│  - раздаёт live-просмотр без повторных pull с камер    │
│  - host network mode в Docker                          │
│  - автопереподключение с экспоненциальной задержкой    │
│ Отказ аналитики НЕ влияет на запись.                   │
├────────────────────────────────────────────────────────┤
│ СЛОЙ АНАЛИТИКИ (Analytics Layer)                       │
│ Worker'ы только для камер в режиме "analytics":        │
│  - детекция по ОСНОВНОМУ потоку либо субпотоку         │
│    с разрешением не ниже 640×480                       │
│  - распознавание, эмбеддинги, кластеризация, апскейл   │
│ Отказ записи НЕ влияет на аналитику.                   │
├────────────────────────────────────────────────────────┤
│ СЛОЙ ПРИЛОЖЕНИЯ                                        │
│ FastAPI + React + PostgreSQL + Redis + Nginx           │
└────────────────────────────────────────────────────────┘
```

**Требования к архитектуре:**
- Слои не имеют общих узких мест: падение/деградация одного не затрагивает другой
- Камера имеет режим: `record_only` (по умолчанию) или `analytics`
- Переключение режима через веб-интерфейс без перезапуска слоёв
- Количество камер в каждом режиме — конфигурируемо

### 3. Управление камерами

- Параметры: название, RTSP-URL основного и субпотока, локация, статус активности, режим

- Непрерывная запись основных потоков всех камер

- Калькулятор хранения в админ-панели

### 6. Детекция движения
- Настраиваемая чувствительность для каждой камеры
- Зоны детекции (ROI) — рисование полигонов поверх кадра
- Расписание детекции (день/ночь, рабочие часы)
- Запись только при движении (опционально)
- Алерты при детекции (Telegram, email, звук)

### 7. Поиск по архиву
- Быстрый поиск по времени, камере, событию
- Поиск по архиву ≤ 5 секунд на объёме до 500 000 сегментов
- Миниатюры кадров для быстрого просмотра
- Экспорт найденных фрагментов

### 8. Отчёты
- Экспорт в Excel/CSV: события, активность по камерам, статистика
- Настраиваемые шаблоны отчётов
- Автоматическая отправка по расписанию (email)

### 9. Дашборд и мониторинг

- Графики посещаемости, тепловая карта часов пик
- Системный мониторинг: CPU/RAM, температура, место на диске
- Статус всех RTSP-потоков (онлайн/оффлайн, FPS, битрейт)
- Алерты: потеря потока, пропуск записи, переполнение диска

### 10. Управление пользователями
- Роли: администратор, оператор, наблюдатель
- Матрица прав на каждую функцию
- Журнал аудита всех действий пользователей

### 11. Настройки системы
- Глобальные настройки: retention, пороги алертов, профили производительности
- Настройки по камерам: retention, ROI, режим, параметры записи

### 13. Отказоустойчивость

## 15. 🎯 Уникальное конкурентное преимущество: Модуль распознавания лиц

**Это то, что отличает FaceWatch от стандартных NVR.**

### Детекция и распознавание лиц
- Только для камер в режиме `analytics` (количество настраивается)
- Детекция ≥ 5 FPS/канал на камерах analytics
- Источник кадров: основной поток либо субпоток с разрешением ≥ 640×480
- Извлечение эмбеддингов 512D, сравнение по косинусному расстоянию
- Автоматическая идентификация известных лиц / регистрация неизвестных
- Порог схожести настраивается (0.1-0.9)

### Карточки персон и кластеризация
- Автоматическая кластеризация неизвестных лиц (DBSCAN)
- Ручное слияние кластеров, назначение имён
- Галерея фотографий для каждой персоны
- Заметки, теги, watchlist (для алертов)

### Нейросетевой апскейл лиц
- Асинхронное улучшение качества скриншотов (CodeFormer/GFPGAN)
- Ленивый режим: по запросу либо фоновой апскейл только аватара
- Не влияет на скорость live-детекции
- Улучшает точность распознавания и поиска похожих лиц

### Поиск похожих лиц (Reverse Face Search)
- Загрузка фото, сравнение с базой
- Поиск ≤ 3-5 секунд на базе до 100 000 лиц (HNSW-индекс pgvector)
- Фильтры: по времени, камере, порогу схожести

### Стена распознавания (Live Face Feed)
- Лента в реальном времени с камер analytics
- Цветовые статусы: известный/неизвестный/watchlist
- Фильтры и поиск по ленте
- Подмена на улучшенное фото (если есть апскейл)

### Зоны детекции (ROI) для аналитики
- Веб-редактор полигонов для камер analytics
- Детекция только в заданных зонах (снижение нагрузки)

### Профили производительности аналитики
- **Экономный:** префильтр движения + пропуск кадров + лёгкая модель
- **Стандартный:** префильтр + каждый второй кадр + средняя модель
- **Максимальный:** каждый кадр + тяжёлая модель
- Профиль применяется ТОЛЬКО к слою аналитики, запись не затрагивается

## 16. Планирование ресурсов (вместо фиксированных чисел)

Вместо хардкода «120 камер» или «2 аналитики» — **формулы и калькуляторы**:

### Слой записи
- **CPU:** ~0.02-0.04 ядра на камеру (MediaMTX remux)
- **RAM:** ~50-100 MB на камеру (буферы)
- **Сеть:** сумма битрейтов всех камер + 10% запас
- **Диск:** формула `Mbps × 10.8 = GB/сутки на камеру`

### Слой аналитики
- **CPU:** зависит от модели и FPS:
  - MobileFaceNet CPU: ~0.5-1.5 ядра на камеру (5 FPS)
  - С GPU: ~0.1 ядра CPU + GPU на камеру
- **RAM:** ~500 MB-2 GB на камеру (модель + буферы)
- **Ограничение:** количество камер analytics определяется доступными ресурсами

### Калькулятор в админ-панели
Ввод: количество камер, битрейт, дни хранения, количество камер analytics  
Вывод: требуемые CPU/RAM/диск, прогноз производительности

### Автоконфигурация при первом запуске
Система определяет доступные ресурсы и предлагает:
- Максимальное количество камер записи
- Максимальное количество камер analytics
- Рекомендуемый профиль производительности

- Добавление GPU для увеличения количества камер analytics

- Быстрые диски (NVMe) для ускорения записи/чтения

### NUMA-оптимизация (для многопроцессорных серверов)
- Привязка воркеров к NUMA-нодам
- Камеры 1-60 на node 0, 61-120 на node 1 (пример для 120 камер)

## 21. Рекомендуемый стек

- **Бэкенд:** Python 3.11+ / FastAPI + WebSocket
- **Запись:** MediaMTX (native record, remux); fallback FFmpeg `-c copy`
- **Видео (аналитика):** OpenCV / FFmpeg (CPU-декод), GStreamer опционально
- **Лица:** MobileFaceNet / YOLOv8n-face + ONNX Runtime CPU / OpenVINO
- **Апскейл:** CodeFormer/GFPGAN (CPU или GPU)
- **Кластеризация:** scikit-learn DBSCAN (пакетно)
- **БД:** PostgreSQL 15+ с pgvector
- **Кэш/очереди:** Redis
- **Веб:** Nginx
- **Мониторинг:** Prometheus-экспортёр + встроенный дашборд (Grafana опционально)
- **Логи:** stdout → ротация / Loki
- **CI/CD:** GitHub Actions
- **Тесты:** pytest, Jest, locust
- **Контейнеризация:** Docker + docker-compose (Windows и Linux)
