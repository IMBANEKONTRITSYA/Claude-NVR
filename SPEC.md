# FaceWatch — система видеонаблюдения с распознаванием лиц
## Версия: Tier 1 (Production / Enterprise Ready)

## Вводные
- **Камеры:** IP-камеры с RTSP-потоком, 5–16 штук
- **Развёртывание:** локально на одном ПК **под Windows** (Windows 10/11 Pro) с возможностью масштабирования
- **Железо:** AMD Ryzen 9 9900X (12C/24T), 32 GB RAM (рекомендуется), GPU опционально
- **Запуск:** одной командой — через Docker Desktop или батник, с автоматической проверкой зависимостей
- **Хранение:** запись видео только при движении/обнаружении лица, автоудаление через N дней, гибкая политика хранения
- **Авторизация:** 3 роли — администратор, оператор, наблюдатель, с детальной матрицей прав
- **Стек:** Python/FastAPI + React + PostgreSQL + Redis (рекомендация, но допускается выбор исполнителя)
- **Интерфейс:** русский язык, тёмная тема, адаптивный дизайн
- **Статус:** Production-Ready, с полным набором документации и инструментов эксплуатации

## Основные функции (сохранено из предыдущей версии)

### 1. Управление камерами
- Добавление, редактирование, удаление IP-камер через веб-интерфейс
- Параметры: название, RTSP-URL, локация, статус активности
- Индикаторы состояния, массовое управление

### 2. Просмотр видео в реальном времени
- Мозаичный режим (грид до 16 камер) и полноэкранный режим
- Bounding box'ы вокруг лиц с подписями
- Задержка ≤3 секунд

### 3. Видеоархив
- Событийная запись, фильтры, плеер, экспорт фрагментов
- Настраиваемая глубина хранения, циклическая перезапись
- Индикация заполнения диска

### 4. Детекция и распознавание лиц
- Детекция ≥5 FPS/канал, извлечение эмбеддингов, сравнение
- Автоматическая идентификация известных / регистрация неизвестных

### 5. Нейросетевой апскейл лиц
- Асинхронное улучшение качества скриншотов (CodeFormer)
- Не влияет на скорость live-детекции, использует многопоточность Ryzen 9
- Улучшение точности распознавания и поиска похожих лиц

### 6. Карточки персон и кластеризация
- Умная кластеризация неизвестных (DBSCAN), ручное слияние, назначение имён

### 7. Дашборд статистики
- KPI, графики посещаемости, топ персон, тепловая карта часов пик

### 8. Стена распознавания (Live Face Feed)
- Лента в реальном времени, цветовые статусы, фильтры

### 9. Настройка зон детекции (ROI)
- Веб-редактор полигонов, снижение нагрузки

### 10. Поиск похожих лиц (Reverse Face Search)
- Загрузка фото, сравнение с базой, просмотр результатов

### 11. Отчёты
- Экспорт в Excel/CSV по персонам, камерам, результатам поиска

## Production-требования Tier 1 (добавлено)

### 12. Отказоустойчивость и мониторинг
- **Мониторинг состояния системы:**
  - Дашборд администратора с метриками: загрузка CPU/RAM, температура, место на диске, состояние всех сервисов, количество активных камер, FPS по каждой камере
  - Ведение логов: структурированные логи (JSON) с ротацией, уровни DEBUG/INFO/WARN/ERROR
  - Централизованный сбор логов (Loki или аналог) для удобного поиска
- **Алертинг:**
  - Настраиваемые пороги: загрузка CPU > 90%, диск заполнен > 90%, потеря сигнала камеры, падение FPS ниже порога
  - Уведомления: Telegram-бот, email, визуальный индикатор в интерфейсе
  - Интеграция с внешними системами мониторинга (Prometheus + Grafana) через экспорт метрик в формате Prometheus
- **Автоматическое восстановление:**
  - Перезапуск упавших сервисов (через Docker restart policy или supervisor)
  - Автопереподключение к RTSP-потокам с экспоненциальной задержкой
  - Graceful shutdown и сохранение состояния при остановке системы
- **Резервное копирование:**
  - Автоматический бэкап базы данных PostgreSQL раз в сутки (сохранять на отдельный диск / сетевое хранилище)
  - Возможность ручного запуска бэкапа
  - Документированная процедура восстановления из бэкапа

### 13. Безопасность (Enterprise Grade)
- **Аутентификация и авторизация:**
  - Парольная политика (сложность, срок действия)
  - Защита от brute-force (ограничение попыток входа, временная блокировка)
  - JWT-токены с refresh-механизмом, автоматический logout при неактивности
- **Защита данных:**
  - Все пароли хэшированы (bcrypt с солью)
  - RTSP-учётные данные и секреты хранятся в зашифрованном виде (AES-256)
  - Полное шифрование данных на уровне приложения при передаче по сети (TLS/HTTPS) — даже внутри локальной сети рекомендуется
- **Сетевая безопасность:**
  - Файрволл, ограничение доступа к админ-панели по IP (опционально)
  - Reverse proxy (Nginx) с настройками безопасности (заголовки, rate limiting)
- **Аудит действий:**
  - Логирование всех операций пользователей: вход/выход, просмотр камер, изменение настроек, экспорт данных
  - Журнал аудита доступен только администратору, защищён от удаления
- **Защита от атак:**
  - OWASP Top 10: защита от XSS, CSRF, SQL-инъекций, инъекций команд ОС
  - Регулярное обновление зависимостей (автоматическая проверка уязвимостей)

### 14. CI/CD и DevOps
- **Контейнеризация:**
  - Весь проект описан в docker-compose.yml с разделением на сервисы: app, db, redis, nginx, media-server, worker-апскейла
  - Использование multi-stage сборок для минимизации образов
- **Автоматическая сборка и тестирование:**
  - GitHub Actions / GitLab CI: при каждом пуше запуск линтеров, юнит-тестов, интеграционных тестов
  - Сборка Docker-образов и публикация в Container Registry
- **Развёртывание:**
  - Одноразовый скрипт развёртывания на Windows: проверка Docker Desktop, настройка окружения, запуск `docker-compose up -d`
  - Поддержка обновлений «на лету» с минимальным простоем (rolling update для stateless-сервисов)
- **Тестирование:**
  - Покрытие кода тестами не менее 70% (back-end)

## 18. Оптимизация для маломощного оборудования (ключевой раздел)

Система должна работать по принципу промышленного NVR: максимальная эффективность при минимальном потреблении ресурсов. Ниже перечислены обязательные архитектурные решения и настройки, которые разработчик должен реализовать.

### 18.1. Двухпоточная работа с камерами
- Каждая камера предоставляет два RTSP-потока: **основной** (высокое разрешение, для записи и просмотра) и **субпоток** (низкое разрешение, для детекции лиц)
- **Субпоток:** 640×360 или 640×480, 5–10 FPS — именно на нём работает детекция лиц, извлечение эмбеддингов
- **Основной поток:** используется для записи в архив и отображения в интерфейсе, не участвует в аналитике
- Интерфейс управления камерами должен позволять указать оба RTSP-URL

### 18.2. Аппаратное ускорение (обязательно)
- Декодирование видеопотоков через **GPU** (Intel QuickSync, NVIDIA NVDEC, AMD VCE) — снижает нагрузку на CPU в 5–10 раз
- Инференс нейросетей на GPU (CUDA, DirectML для Windows, ONNX Runtime с GPU-бэкендом)
- Если GPU нет — инференс на CPU, но с использованием **OpenVINO** (оптимизация Intel) или ONNX Runtime CPU
- Автоопределение доступного ускорителя при запуске, fallback на CPU

### 18.3. Адаптивная частота детекции (пропуск кадров)
- Настройка "интервал детекции": анализировать каждый N-й кадр (1, 2, 3, 5, 10)
- Динамическое снижение FPS детекции, когда в кадре длительное время нет движения (например, снижать до 1 FPS)
- Мгновенный возврат к полной частоте при обнаружении движения или лица
- Регулировка через конфигурационный файл и админ-панель

### 18.4. Детекция движения как префильтр
- Перед запуском тяжёлого детектора лиц — быстрая проверка движения в кадре (OpenCV MOG2 / KNN)
- Детектор лиц запускается только на тех кадрах, где обнаружено движение
- **Снижает нагрузку в 3–5 раз** для сцен, где люди появляются редко
- Настройка чувствительности детектора движения для каждой камеры

### 18.5. Легковесные модели нейросетей
- Использование уменьшенных моделей для детекции лиц: YOLOv8-nano-face (самая лёгкая), CenterFace, UltraFace
- Для извлечения эмбеддингов: MobileFaceNet вместо тяжёлых ResNet-вариантов
- Возможность переключения на более точные модели (InsightFace buffalo_l) для мощного железа — настройка в конфиге
- Апскейл: легковесный вариант CodeFormer или быстрый бикубический апскейл с повышением резкости (для слабого CPU)

### 18.6. Ленивый апскейл и фоновая кластеризация
- **Апскейл:** не для каждого лица в реальном времени, а только когда пользователь открывает карточку персоны или запускает вручную
- Дополнительная опция: апскейл в фоне только для лучшего кадра каждой персоны (аватар), а не всей галереи
- **Кластеризация:** не в реальном времени при каждом обнаружении, а пакетная обработка раз в N минут (настраивается: 1, 5, 15, 60 минут)
- Все фоновые задачи (апскейл, кластеризация) выполняются с **низким приоритетом процесса** (nice/idle priority в Windows), чтобы не мешать основному функционалу

### 18.7. Интеграция с ONVIF-событиями камер
- Если камера поддерживает ONVIF Profile G/S — получать события движения и детекции людей напрямую от камеры
- Камера сама сообщает «в кадре движение/человек» — тогда детектор лиц запускается только по этим триггерам
- **Максимальная экономия ресурсов** — камера делает предобработку на своём чипе
- Поддержка ONVIF в интерфейсе: автообнаружение камер в сети, получение профилей потоков

### 18.8. Оптимизация хранения
- Запись видео в **H.265** (более эффективное сжатие, чем H.264, экономия до 50% места)
- Настройка битрейта записи для каждой камеры в админ-панели
- Возможность записи только ключевых кадров (I-frames only) для максимальной экономии места

### 18.9. Профили производительности
- **«Экономный»** — только детекция лиц на субпотоке, пропуск 3 кадров, префильтр движения, MobileFaceNet, апскейл только по запросу, кластеризация раз в 60 минут
- **«Стандартный»** — детекция на субпотоке, пропуск 1 кадра, префильтр движения, InsightFace buffalo_s, апскейл аватаров в фоне, кластеризация раз в 15 минут
- **«Максимальный»** — детекция на субпотоке без пропусков, без префильтра (анализ каждого кадра), InsightFace buffalo_l, апскейл всей галереи в фоне, кластеризация раз в 5 минут
- Выбор профиля в админ-панели, возможность ручной кастомизации каждого параметра

## Технические требования (обновлено)
- До 16 камер одновременно
- **Экономный режим:** 8 камер × 5 FPS детекции на Intel N100 с загрузкой CPU < 50%
- **Стандартный режим:** 12 камер × 10 FPS детекции на Core i3 с загрузкой CPU < 60%
- Задержка трансляции ≤3 сек, поиск по архиву ≤5 сек
- Система стабильно работает 24/7 без деградации
- Время восстановления после сбоя ≤5 минут, целевая доступность 99.5%
- Все компоненты в Docker с лимитами ресурсов

## Рекомендуемый стек (расширен для Tier-1 + оптимизации)
- Бэкенд: Python 3.11+ / FastAPI + WebSocket
- Видео: OpenCV (сборка с GPU-бэкендом: CUDA, DirectML или OpenVINO) + FFmpeg с аппаратным кодированием
- Лица: InsightFace (MobileFaceNet) или YOLOv8-nano-face + ONNX Runtime
- Апскейл: CodeFormer (CPU-лёгкий) или бикубический фильтр + unsharp mask
- Аппаратное ускорение: OpenVINO для Intel, ONNX Runtime DirectML для AMD/NVIDIA на Windows
- Кластеризация: scikit-learn (DBSCAN, пакетный запуск)
- БД: PostgreSQL 15+ с pgvector
- Кэш/очереди: Redis
- Медиасервер: MediaMTX
- Веб-сервер: Nginx (Windows)
- Мониторинг: Prometheus + Grafana (опционально)
- Логирование: stdout → Loki или Docker driver
- CI/CD: GitHub Actions
- Тестирование: pytest, Jest, locust
- Контейнеризация: Docker Desktop for Windows + docker-compose
