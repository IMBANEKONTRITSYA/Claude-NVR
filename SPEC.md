# FaceWatch — система видеонаблюдения с распознаванием лиц
## Версия: Tier 1 (Production / Enterprise Ready) — Scale Edition

## 1. Вводные

- **Масштаб объекта:** 120 IP-камер в здании, у каждой 2 RTSP-потока
- **Конфигурация камер (базовая, фактическая):**
  - Основной поток: H.265, 1280×720 @ 15 fps, 2048 kbps, VBR, smart-кодек
  - Субпоток: H.265, 352×288 (CIF) @ 10 fps, 256 kbps, CBR
- **Принцип разделения (ключевой):** запись и аналитика — независимые слои.
  Запись ведётся по всем 120 камерам без декодирования (remux).
  Аналитика (детекция/распознавание лиц) — только на N выбранных камерах
  (по умолчанию 2), конфигурируется в интерфейсе.
- **Развёртывание:** Docker (docker-compose), запуск одной командой.
  Целевые платформы: Windows 10/11 Pro (разработка, малые объекты)
  и Linux-сервер (production, полный масштаб).
- **Целевой production-сервер:** 2× Intel Xeon E5-2670 (32C/64T), 128 GB DDR3,
  без GPU. GPU опционален для масштабирования аналитики.
- **Хранение:** запись только основного потока; событийная аналитика по суб/основному;
  автоудаление по retention-политике; циклическая перезапись.
- **Авторизация:** 3 роли (администратор, оператор, наблюдатель) с матрицей прав.
- **Стек:** Python 3.11+/FastAPI + WebSocket, React, PostgreSQL 15+ (pgvector),
  Redis, MediaMTX, Nginx.
- **Интерфейс:** русский язык, тёмная тема, адаптивный дизайн.
- **Статус:** Production-Ready с полным набором документации и инструментов эксплуатации.

## 2. Архитектура: два независимых слоя (обязательно)

    ┌────────────────────────────────────────────────────────┐
    │ СЛОЙ ЗАПИСИ (Recording Layer)                          │
    │ MediaMTX (один процесс):                               │
    │  - тянет основные потоки всех 120 камер (1 pull/камера)│
    │  - пишет remux-сегменты на диск БЕЗ декодирования      │
    │  - раздаёт live-просмотр без повторных pull с камер    │
    │  - host network mode в Docker                          │
    │  - автопереподключение с экспоненциальной задержкой    │
    │ Отказ аналитики НЕ влияет на запись.                   │
    ├────────────────────────────────────────────────────────┤
    │ СЛОЙ АНАЛИТИКИ (Analytics Layer)                       │
    │ Worker'ы только для камер в режиме "analytics":        │
    │  - детекция по ОСНОВНОМУ потоку (720p) либо субпотоку  │
    │    с разрешением не ниже 640×480                       │
    │  - распознавание, эмбеддинги, кластеризация, апскейл   │
    │ Отказ записи НЕ влияет на аналитику.                   │
    ├────────────────────────────────────────────────────────┤
    │ СЛОЙ ПРИЛОЖЕНИЯ                                        │
    │ FastAPI + React + PostgreSQL + Redis + Nginx           │
    └────────────────────────────────────────────────────────┘

Требования:
- Слои не имеют общих узких мест: падение/деградация одного не затрагивает другой.
- Камера имеет режим: `record_only` (по умолчанию) или `analytics`.
- Переключение режима — через веб-интерфейс, без перезапуска слоёв.

## 3–13. Основные функции

### 3. Управление камерами
- Добавление, редактирование, удаление IP-камер через веб-интерфейс
- Параметры: название, RTSP-URL основного и субпотока, локация, статус активности,
  **режим (record_only/analytics)**
- ONVIF: автообнаружение камер в сети, получение профилей потоков
- Индикаторы состояния, массовое управление
- Scale Edition: для 120 камер — обязательна группировка/пагинация в интерфейсе

### 4. Просмотр видео в реальном времени
- Мозаичный режим (грид до 16 камер) и полноэкранный режим; для 120 камер — выбор
  группы/страницы
- Bounding box'ы вокруг лиц с подписями (только для камер в режиме analytics)
- Задержка ≤ 3 секунд
- Scale Edition: live-трансляция через MediaMTX (один pull с камеры на всех зрителей)

### 5. Видеоархив
- Непрерывная запись основных потоков всех камер; фильтры, плеер, экспорт фрагментов
- Настраиваемая глубина хранения (глобально и по камерам), циклическая перезапись
- Индикация заполнения диска, прогноз «на сколько дней хватит места»

### 6. Детекция и распознавание лиц
- Детекция ≥ 5 FPS/канал, извлечение эмбеддингов, сравнение
- Автоматическая идентификация известных / регистрация неизвестных
- Scale Edition: только для камер в режиме `analytics` (по умолчанию 2);
  источник кадров — основной поток (720p) либо субпоток с разрешением не ниже 640×480.
  **CIF (352×288) для детекции не используется** (недостаточно пикселей на лицо)

### 7. Нейросетевой апскейл лиц
- Асинхронное улучшение качества скриншотов (CodeFormer)
- Не влияет на скорость live-детекции, использует многопоточность
- Улучшает точность распознавания и поиска похожих лиц
- Scale Edition: ленивый режим (по запросу либо фоновой апскейл только аватара);
  CPU-оптимизация с учётом отсутствия AVX2 на целевом сервере

### 8. Карточки персон и кластеризация
- Умная кластеризация неизвестных (DBSCAN), ручное слияние, назначение имён
- Scale Edition: кластеризация пакетная (раз в N минут, настраивается),
  с низким приоритетом процесса

### 9. Дашборд статистики
- KPI, графики посещаемости, топ персон, тепловая карта часов пик
- Scale Edition: сводка слоя записи — активные потоки (из 120), количество и объём
  сегментов за сутки, прогноз свободного места (детали мониторинга — в §14)

### 10. Стена распознавания (Live Face Feed)
- Лента в реальном времени, цветовые статусы, фильтры
- Scale Edition: лента формируется только с камер в режиме `analytics`

### 11. Настройка зон детекции (ROI)
- Веб-редактор полигонов, снижение нагрузки
- Scale Edition: доступно только для камер в режиме `analytics`

### 12. Поиск похожих лиц (Reverse Face Search)
- Загрузка фото, сравнение с базой, просмотр результатов
- Scale Edition: время поиска ≤ 3–5 сек на базе до 100 000 лиц (см. §26)

### 13. Отчёты
- Экспорт в Excel/CSV по персонам, камерам, результатам поиска
- Scale Edition: операции экспорта фиксируются в журнале аудита (см. §15)

## 14. Отказоустойчивость и мониторинг (сохранено + дополнено)

## 19. Оптимизация (пересмотрено под новый масштаб)

- **Запись без декодирования:** remux H.265-битстрима как есть (MediaMTX native record;
  fallback — FFmpeg `-c copy`). Никакого перекодирования в слое записи.
- **Аналитика на лёгких моделях:** MobileFaceNet / YOLOv8n-face по умолчанию
  (CPU, без AVX2); ONNX Runtime CPU / OpenVINO; автоопределение ускорителя с fallback.
- **Префильтр движения** (MOG2/KNN) перед детектором на камерах analytics;
  ONVIF-события движения как триггер, если камера поддерживает.
- **Адаптивная частота детекции:** анализ каждого N-го кадра (1/2/3/5/10),
  снижение до 1 FPS при отсутствии движения, мгновенный возврат при появлении.
- **Ленивый апскейл и пакетная кластеризация** с низким приоритетом процесса.
- **Профили производительности** сохранены (Экономный/Стандартный/Максимальный),
  применяются только к слою аналитики; слой записи всегда в режиме remux.

## 20. Подсистема записи на 120 камер (новый раздел)

- MediaMTX — единственный процесс, пишущий все камеры; не использовать
  120 отдельных FFmpeg-процессов.
- Сегменты 5–10 минут, именование `cam{camera_id}_{unix_ts}.mp4`.
- Запись ТОЛЬКО основного потока. Субпоток в архив не пишется.
- host network mode для медиасервиса (избегать NAT-overhead на сотнях Mbps).
- Health-check каждого потока; при потере — реконнект с экспоненциальной задержкой;
  событие в аудит и алертинг.
- Целевая нагрузка слоя записи на целевом сервере: 2–4 ядра из 64, ~30 MB/s записи.

## 21. Хранение и архив (новый раздел)

- Формула расчёта: `Mbps × 10.8 = GB/сутки на камеру`.
- Базовый расчёт при текущих настройках (основной 2 Mbps):
  - на камеру: 21.6 GB/сутки
  - 120 камер: ~2.6 TB/сутки (номинал); с учётом VBR/smart-кодек фактически ~1.6–2 TB/сутки
  - 7 дней ≈ 18 TB; 14 дней ≈ 36 TB; 30 дней ≈ 78 TB
- Retention по умолчанию 14 дней, настраивается глобально и по камерам.
- Дисковая подсистема: mirror/RAID (надёжность, не скорость); sustained write 30 MB/s
  переваривается HDD; page cache (большой RAM) сглаживает пики.
- Админ-панель: калькулятор хранения (битрейт × камеры × дни → требуемый объём),
  индикация заполнения, алерты 80%/90%, автоудаление старейших сегментов при переполнении.
- Калибровка: после 24 ч работы система сравнивает номинальный и фактический расход
  и показывает скорректированный прогноз.

## 22. Сеть (новый раздел)

- Фактический трафик при базовой конфигурации: 120 × (2 + 0.256) ≈ **270 Mbps**
  (~29% гигабитного линка). 1 Gbps достаточно с трёхкратным запасом.
- Требования: аплинки коммутаторов здания суммарно ≥ 1 Gbps до сервера;
  RTSP over TCP; выделенная VLAN для камер рекомендуется.
- 10GbE НЕ является обязательным требованием; рекомендуется только при росте
  битрейтов/числа камер аналитики с live-декодированием.

## 23. Целевой сервер и NUMA (новый раздел)

- Production: 2× Xeon E5-2670 (32C/64T), 128 GB DDR3, без GPU.
- NUMA: воркеры записи и аналитики распределяются по нодам
  (`numactl --cpunodebind/--membind`): камеры 1–60 на node 0, 61–120 на node 1.
- Бюджет CPU: запись ~2–4 ядра, аналитика (2 камеры) ~2–3 ядра, приложение ~2 ядра;
  суммарно ≤ 20% при полной нагрузке.
- Отсутствие AVX2 учитывать при выборе моделей и библиотек (бенчмарк инференса на целевом CPU в CI).
- Масштабирование аналитики: при росте числа камер analytics сверх 8–10 —
  добавление GPU класса GTX 1060 и выше (CUDA) либо вынос Face Engine на отдельный узел.

## 24. Явно вне рамок текущей версии (не реализовывать)

- Детекция лиц на всех 120 камерах без GPU.
- Запись субпотоков в архив.
- Обязательность 10GbE.
- Перекодирование архива (только remux).
- Репликация PostgreSQL primary-replica — задел на будущее, не в текущей версии.

## 26. Технические требования (пересмотрено)

- 120 камер в режиме записи (remux) + N камер аналитики (по умолчанию 2).
- Запись: 0 пропущенных сегментов при штатной работе; восстановление потока ≤ 5 с.
- Аналитика: детекция ≥ 5 FPS/канал на камерах analytics; задержка live ≤ 3 с.
- Поиск по архиву ≤ 5 с; поиск по фото ≤ 3–5 с на базе до 100 000 лиц.
- Апскейл ≤ 200 мс/лицо асинхронно.
- CPU ≤ 20% на целевом сервере при полной нагрузке (120 запись + 2 аналитика).
- RAM ≤ 20 GB на целевом сервере.
- 24/7 без деградации; RTO ≤ 5 минут; доступность 99.5%.
- Все компоненты в Docker с лимитами ресурсов; медиасервис — host network.

## 28. Рекомендуемый стек (дополнен)

- Бэкенд: Python 3.11+ / FastAPI + WebSocket
- Запись: **MediaMTX (native record, remux)**; fallback FFmpeg `-c copy`
- Видео (аналитика): OpenCV / FFmpeg (CPU-декод), GStreamer опционально
- Лица: MobileFaceNet / YOLOv8n-face + ONNX Runtime CPU / OpenVINO
- Апскейл: CodeFormer CPU-light или бикубический + unsharp mask
- Кластеризация: scikit-learn DBSCAN (пакетно)
- БД: PostgreSQL 15+ с pgvector; Кэш/очереди: Redis
- Веб: Nginx; Мониторинг: Prometheus-экспортёр + встроенный дашборд (Grafana опционально)
- Логи: stdout → ротация / Loki
- CI/CD: GitHub Actions; Тесты: pytest, Jest, locust
- Контейнеризация: Docker + docker-compose (Windows и Linux)
