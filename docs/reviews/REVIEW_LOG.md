## ⚠️ Обнаружен конкурентный запуск сессий (циклы 9-10)
Цикл 9 нашёл прямые доказательства минимум двух независимых автоматических
сессий, работавших на `claude/pensive-brown-28588t` **одновременно** в одном
временном окне — обе датировали себя «циклом 8», обе описывают работу над
пересекающимися PR (#27/#28) от первого лица с деталями, которые не
подделать постфактум. Цикл 10 не нашёл новых прямых улик, но стартовал с
уже открытым и готовым (не самим им созданным) PR #29 — состояние,
согласующееся с тем же паттерном. Цикл 11 не нашёл новых улик (чистый
старт, чистый финиш — см. `REVIEW-2026-08-04T182309Z.md`), но это не
опровергает риск: находка остаётся вероятностной, зависит от того,
пересеклись ли по времени два расписания в конкретном окне. Подробности —
раздел «Конкурентный запуск» в `REVIEW-2026-08-04T161845Z.md` (полное
описание), `REVIEW-2026-08-04T163032Z.md` (подтверждение) и
`REVIEW-2026-08-04T182309Z.md` (чистый цикл, риск не снят). Три цикла без
дублирующих PR или конфликтов мерджа — это везение, не гарантия;
**приоритет №1 для стороны оркестрации остаётся без изменений.**

## Известные пробелы, перенесённые в следующие циклы
(из REVIEW-2026-08-04T182309Z — актуально до следующего аудита)
- **Конкурентный запуск сессий на одной ветке** — см. предупреждение выше, приоритет №1, чинится только на стороне оркестрации расписания
- Разночтение назначенной ветки харнесса vs фактической ветки с кодом на origin — устойчивый паттерн все 11 циклов, стоит проверить на стороне оркестрации сессий
- Удаление смерджённых веток `fix/*`/`docs/*`/`feat/*`/`test/*` — `git push --delete` получает HTTP 403 от прокси песочницы 11 циклов подряд; отдельного `delete_branch` в доступных GitHub MCP-инструментах тоже нет; нужна ручная очистка или расширение прав на стороне оркестрации (циклы 7-11 не повторяют попытку сверх однократной проверки за цикл, см. рекомендацию цикла 6)
- Полноценный проход по P0/P1 не проводился с цикла 7 (4 цикла назад) — с тех пор добавлены новые ONVIF-эндпоинты и конфиг-поля записи; рекомендуется освежить в ближайшем цикле
- ТЗ 18.2 (аппаратное ускорение — и инференс, и декодирование) реализовано полностью на уровне кода с цикла 11, но ни разу не проверялось на реальном GPU за все 11 циклов (песочница без GPU) — нужен цикл с реальным железом для содержательной проверки
- Docker daemon недоступен шестой цикл подряд (циклы 6-11); в цикле 11 реальная БД не потребовалась (менялась только worker-логика без БД-зависимостей) — Postgres+pgvector+Redis через `postgresql-16-pgvector`+`redis-server` в песочнице остаётся официальным fallback для циклов, где БД нужна
- SPEC 18 (весь раздел «Оптимизация для маломощного оборудования») теперь закрыт полностью на уровне кода — следующим циклам не нужно возвращаться к нему за новыми пробелами, только за подтверждением на реальном железе (18.2, см. выше)
