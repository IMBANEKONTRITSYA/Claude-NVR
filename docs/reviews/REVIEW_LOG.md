## Известные пробелы, перенесённые в следующие циклы
(актуальная часть — из REVIEW-2026-08-05T181442Z, цикл 20; ниже — более
ранние пункты, ещё не закрытые)

- **Сервис апскейла отстаёт от остальных по «обвязке» (цикл 20).** Три
  связанных пункта, все — в `upscaler/upscaler.py`, чинятся одной правкой:
  весь вывод идёт через `print(..., flush=True)` вместо
  `logging_utils.configure_logging` (единственный сервис без JSON-логов с
  ротацией, ТЗ P1); `main()` крутит `while True` без `shutdown_event`, то
  есть graceful shutdown нет, в отличие от воркера; `create_engine`
  вызывается без `pool_size` (дефолтные 5). Сам сервис в цикле 20 впервые
  получил тесты и CI-джобу — до этого 20 циклов был полностью непокрыт.
- **Изоляция тестов бэкенда** (перенесено из цикла 19, не тронуто циклом
  20): часть интеграционных тестов создаёт пользователей и не удаляет их,
  тест лимита попыток оставляет счётчики в Redis. В CI не видно (свежие
  сервис-контейнеры), но повторный локальный прогон по той же БД даёт
  ложные падения.
- **Приём для повторного использования (цикл 20):** скан блоков
  `with Session()` на предмет вызовов ввода-вывода внутри — двадцать строк
  на `re` с разбором по отступу. Даёт карту удержаний соединения за
  секунды вместо чтения 1300 строк глазами; стоит прогонять после каждого
  изменения в воркере или апскейлере. Класс «сессия БД удерживается через
  ввод-вывод» на момент цикла 20 закрыт во всех трёх сервисах.
- **Урок цикла 20 (тесты):** любой тест, где проверяемое свойство зависит
  от времени выполнения, обязан фиксировать время (`monkeypatch` на
  `time.time`), а не надеяться на скорость машины. Первая версия теста на
  уникальность имён снимков проходила без фикса, потому что два
  `cv2.imwrite` на реальном диске разъезжались по миллисекундам —
  «подтверждала» исправность сломанной реализации, поймано только
  верификацией откатом. Парный урок: проверять поведение, а не формат —
  тест на формат имени прошёл бы и на реализации, которая добавила суффикс,
  но продолжила перезаписывать файл.
