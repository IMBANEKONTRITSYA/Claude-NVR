# API_DOCS — REST API и WebSocket

FaceWatch backend — FastAPI. Полная, всегда актуальная (автогенерация
из кода) спецификация доступна в самом развёртывании:

- **Swagger UI:** `http://localhost:8000/docs`
- **ReDoc:** `http://localhost:8000/redoc`
- **OpenAPI JSON:** `http://localhost:8000/openapi.json`

Этот документ — карта разделов API и то, чего нет в автогенерируемой
схеме: аутентификация, коды ошибок, формат WebSocket-сообщений.

## Аутентификация

Все эндпоинты, кроме `POST /api/auth/login`, `POST /api/auth/refresh` и
`GET /api/health`, требуют заголовок:

```
Authorization: Bearer <access_token>
```

### Получение токена

```
POST /api/auth/login
Content-Type: application/x-www-form-urlencoded

username=admin&password=...
```

Ответ (`Token`):
```json
{
  "access_token": "...",
  "refresh_token": "...",
  "token_type": "bearer",
  "password_expired": false
}
```

- `access_token` — JWT, HS256, живёт **30 минут** (`ACCESS_TOKEN_EXPIRE_MINUTES`).
- `refresh_token` — живёт **14 дней** (`REFRESH_TOKEN_EXPIRE_DAYS`), хранится
  на сервере в виде хэша; каждое использование ротирует токен (старый
  инвалидируется).
- `password_expired: true` означает, что пароль старше 90 дней — вход
  выполнен, но клиент должен принудительно направить пользователя на
  смену пароля (`/profile`), не блокируя сессию.

### Обновление токена

```
POST /api/auth/refresh
Content-Type: application/json

{"refresh_token": "..."}
```

Возвращает новую пару токенов (та же структура `Token`). Старый
refresh-токен становится недействительным сразу после использования.

### Выход

```
POST /api/auth/logout
Content-Type: application/json

{"refresh_token": "..."}
```

Отзывает переданный refresh-токен на сервере.

### Брute-force защита

Не более **10 попыток входа** за скользящее окно на связку
логин+IP (счётчик в Redis) — после превышения `POST /api/auth/login`
возвращает `429 Too Many Requests` до истечения окна.

## Роли и коды ошибок

Каждый защищённый эндпоинт проверяет роль текущего пользователя
(зависимость FastAPI, читает роль из JWT). Стандартные коды:

| Код | Когда |
|---|---|
| `401 Unauthorized` | токен отсутствует, истёк или недействителен |
| `403 Forbidden` | роль не даёт доступа к операции (см. матрицу прав в USER_GUIDE.md) |
| `404 Not Found` | ресурс не существует или недоступен текущему пользователю |
| `422 Unprocessable Entity` | ошибка валидации тела запроса (Pydantic) |
| `429 Too Many Requests` | превышен лимит попыток входа |

## Разделы API

Полные схемы запросов/ответов — в Swagger (`/docs`), каждый тег ниже
соответствует тегу в OpenAPI-схеме.

| Префикс | Тег | Назначение |
|---|---|---|
| `/api/auth` | `auth` | вход, обновление токена, выход, смена пароля, текущий пользователь |
| `/api/users` | `users` | CRUD пользователей (только админ) |
| `/api/cameras` | `cameras` | CRUD камер, RTSP/ROI, снимок, HLS-адрес, проверка подключения |
| `/api/persons` | `persons` | список/карточка персоны, слияние, галерея, ручной апскейл |
| `/api/events` | `events` | лента событий распознавания (обогащённая: персона + камера) |
| `/api/archive` | `archive` | список видеосегментов, скачивание файла, экспорт фрагмента по границам времени (`GET /api/archive/export`, remux поверх нескольких сегментов) |
| `/api/stats` | `stats` | KPI, графики по дням/часам, тепловая карта, топ персон |
| `/api/reports` | `reports` | экспорт CSV/XLSX (появления, персоны, камеры), шаблоны отчётов и расписание авто-отправки (§8) |
| `/api/search` | `search` | поиск похожих лиц по загруженному фото |
| `/api/settings` | `settings` | системные настройки, профили производительности, тест Telegram и SMTP |
| `/api/audit` | `audit` | журнал аудита, экспорт CSV/XLSX (только чтение) |
| `/api/system` | `system` | метрики мониторинга, хранилище архива и калькулятор (SPEC §21), автоконфигурация по ресурсам сервера (SPEC §16: `GET /api/system/autoconfig`, `POST /api/system/autoconfig/apply`), экспорт Prometheus |
| `/api/media/{kind}/{name}` | — | отдача снимков/аватаров/сегментов, авторизация токеном в query-параметре (нужно для `<img src>`/`<video src>`, которые не могут выставить заголовок `Authorization`) |
| `/api/health` | — | health-check (БД + Redis), без авторизации, используется Docker healthcheck |

## WebSocket-эндпоинты

Не входят в OpenAPI-схему (ограничение спецификации) — описаны здесь.
Оба требуют токен как query-параметр: `?token=<access_token>`.

### `GET /ws/faces`

Живая лента распознанных лиц (используется Стеной и Дашбордом).
Сообщения — JSON, два типа:

**`type: "box"`** — лёгкое сообщение на каждый кадр с лицом в кадре
(для оверлея bounding box на LiveGrid), не создаёт запись в архиве:
```json
{
  "type": "box",
  "camera_id": 1,
  "person_id": 42,
  "name": "Иван Иванов",
  "is_known": true,
  "bbox": {"x1": 100, "y1": 50, "x2": 200, "y2": 180},
  "frame_w": 640,
  "frame_h": 360
}
```

**`type: "face"`** — событие распознавания (создан `FaceEvent`, не чаще
раза в `event_cooldown_sec` на персону на камеру):
```json
{
  "type": "face",
  "event_id": 1001,
  "camera_id": 1,
  "person_id": 42,
  "name": "Иван Иванов",
  "is_known": true,
  "alert": true,
  "snapshot": "snapshots/cam1_...jpg",
  "ts": "2026-08-04T12:00:00",
  "bbox": {"x1": 100, "y1": 50, "x2": 200, "y2": 180},
  "frame_w": 640,
  "frame_h": 360
}
```

Поле `alert` — персона в watchlist (флаг «оповещать» в её карточке). По
нему Стена подаёт звуковой сигнал, если включён `alert_sound_enabled`
(SPEC §6); в `type: "box"` его нет — сигналить на каждый кадр незачем.

Также транслируется `type: "faces:enhanced"` — когда фоновый апскейл
завершает улучшение снимка (обновлённый путь к файлу, для замены
превью на лету без перезагрузки страницы).

### `GET /ws/cameras`

Изменения статуса камер (`online`/`offline`/`disabled`), для
обновления индикаторов в реальном времени:
```json
{"camera_id": 1, "status": "offline"}
```

## Аутентификация в WebSocket и медиа-ссылках

REST-эндпоинты используют заголовок `Authorization: Bearer`, но
браузерные `<img>`, `<video>` и `WebSocket` не могут установить
произвольный заголовок — для них токен передаётся как query-параметр
`?token=...` и проверяется на сервере тем же способом (валидация JWT).
Токен в URL — стандартный компромисс для этих случаев; ссылки не
предназначены для долгосрочного хранения/публикации, так как содержат
короткоживущий access-токен.

## Rate limiting и защита от злоупотреблений

- Вход: не более 10 попыток за окно на логин+IP (см. выше).
- Очередь фонового апскейла ограничена 500 задачами (`upscale:queue` в
  Redis) — при переполнении новые запросы на апскейл отбрасываются
  тихо, чтобы не копить бэклог на слабом CPU; повторный запрос апскейла
  из карточки персоны отправляет задачу заново.
- Nginx перед backend добавляет security-заголовки (`X-Frame-Options`,
  `X-Content-Type-Options`, `Referrer-Policy`, HSTS на HTTPS-хосте) и
  ограничивает частоту запросов к `/api/auth/login` (см.
  `frontend/nginx-locations.conf`) — сверх Redis-счётчика попыток на
  уровне backend, описанного выше.
