# INSTALL — установка FaceWatch на Windows

Подробная инструкция для развёртывания на Windows 10/11 Pro. Краткая версия — в
[README.md](../README.md#запуск-под-windows).

## 1. Требования

### Программное обеспечение

- **Windows 10/11 Pro** (или Enterprise) — Home-редакция тоже подходит, если в ней
  включена виртуализация (WSL2 работает и на Home с 2021 года).
- **Docker Desktop for Windows**: https://www.docker.com/products/docker-desktop/
  - Использует backend **WSL2** (рекомендуется, включается мастером установки Docker
    Desktop) либо Hyper-V.
  - В BIOS/UEFI должна быть включена виртуализация (Intel VT-x / AMD-V) — на
    большинстве ПК включена по умолчанию; если Docker Desktop жалуется на
    "virtualization not enabled", проверьте этот пункт в BIOS.
- Свободный доступ в интернет при первой сборке — скачиваются базовые образы
  (~3–4 ГБ суммарно) и модель InsightFace (buffalo_s/buffalo_l, десятки МБ).

### Железо (см. также SPEC.md §«Минимальные системные требования»)

| Компонент | Минимум (экономный профиль) | Рекомендуется (стандартный) | Максимум |
|---|---|---|---|
| CPU | Intel N100 / Celeron J4125 / AMD Athlon | Core i3-12100 / Ryzen 3 | Core i5+ / Ryzen 5+ |
| RAM | 8 ГБ | 16 ГБ | 32 ГБ |
| Диск | SSD 128 ГБ (система) + HDD 500 ГБ (архив) | SSD 256 ГБ + HDD 1 ТБ | NVMe 512 ГБ + HDD 2+ ТБ |
| Камеры | 4–8 | 8–12 | 12–16 |

GPU не обязателен: без него воркер использует OpenVINO (Intel) или чистый CPU
через ONNX Runtime. При наличии дискретной NVIDIA/AMD-карты ускорение
подключается автоматически (см. `docs/ARCHITECTURE.md`, автоопределение
провайдера ONNX Runtime).

### Сеть

- Камеры и ПК с FaceWatch должны быть в одной локальной сети (или иметь
  маршрутизацию до RTSP-портов камер, обычно 554/TCP).
- Если на ПК включён брандмауэр Windows, при первом запуске Docker Desktop
  спросит разрешение на сетевой доступ — подтвердите (Private network).
- Порты, которые слушает FaceWatch на хосте (см. таблицу в README «Адреса»):
  `8080` (веб, HTTP), `8443` (веб, HTTPS), `8000` (API/Swagger),
  `8554`/`8888`/`8889` (MediaMTX RTSP/HLS/WebRTC — на loopback, для отладки),
  `5432`/`6379` (Postgres/Redis — на loopback, для отладки).

## 2. Установка Docker Desktop

1. Скачайте установщик с https://www.docker.com/products/docker-desktop/
2. Запустите установщик, оставьте опцию **"Use WSL 2 instead of Hyper-V"**
   включённой (по умолчанию).
3. После установки перезагрузите ПК, если попросит инсталлятор.
4. Запустите Docker Desktop и дождитесь, пока иконка в трее станет зелёной
   (статус "Docker Desktop is running").
5. Проверьте в PowerShell:
   ```powershell
   docker --version
   docker compose version
   ```
   Обе команды должны вывести версию без ошибок.

## 3. Получение проекта

Распакуйте архив проекта (или выполните `git clone`) в папку без пробелов и
кириллицы в пути — например, `C:\FaceWatch`. Некоторые Docker-инструменты на
Windows некорректно работают с путями вида `C:\Мои документы\...`.

## 4. Первый запуск

1. Дважды кликните `start.bat` в корне проекта.
2. Скрипт проверит наличие Docker, автоматически создаст `.env` со
   случайными `SECRET_KEY`, `RTSP_ENCRYPTION_KEY` и `ADMIN_PASSWORD`
   (см. `scripts/generate_env.ps1`) — эти значения выводятся в консоль,
   **сохраните их** (пароль администратора понадобится для входа).
3. Выполнится `docker compose up -d --build`. Первая сборка занимает
   **~10 минут** — скачиваются образы (Python, Node, Postgres+pgvector,
   MediaMTX, nginx) и модель распознавания лиц.
4. По готовности автоматически откроется браузер на `http://localhost:8080`.
5. Войдите: логин `admin`, пароль — значение `ADMIN_PASSWORD`, выведенное на
   шаге 2 (также сохранено в файле `.env` в корне проекта).
6. **Сразу смените пароль администратора** в разделе «Профиль» — пароль по
   умолчанию сгенерирован случайно, но полезно завести собственный,
   который вы точно запомните.

Если `generate_env.ps1` не смог выполниться (например, PowerShell
Execution Policy заблокирована через групповую политику), `start.bat`
скопирует `.env.example` в `.env` с **публично известными** значениями
по умолчанию — в этом случае backend откажется стартовать с сообщением
"обнаружены секреты по умолчанию из публичного репозитория" (это
намеренная защита, см. ТЗ 13). Отредактируйте `.env` вручную:
`SECRET_KEY`, `RTSP_ENCRYPTION_KEY`, `ADMIN_PASSWORD` — сгенерировать
ключ Fernet можно командой из README («Конфигурация (.env)»).

## 5. Проверка после установки

- `docker compose ps` — все сервисы должны быть в статусе `running` (или
  `healthy` для тех, у кого настроен healthcheck).
- `http://localhost:8000/api/health` — должен вернуть `{"ok": true, "db": "ok", "redis": "ok"}`.
- `http://localhost:8000/docs` — интерактивная документация API (Swagger UI).
- Раздел «Мониторинг» в веб-интерфейсе (только админ/оператор) — CPU, RAM,
  диск, статус сервисов.

## 6. Добавление первой камеры

См. [USER_GUIDE.md](USER_GUIDE.md#управление-камерами).

## 7. Обновление версии

```powershell
git pull
docker compose up -d --build
```

Данные (база, архив, снимки, аватары) хранятся в именованных docker-томах
(`pgdata`, `media`, `backups`, `frontend_certs`) и не теряются при
пересборке образов. `docker compose down -v` **удаляет** тома — не
используйте эту команду, если хотите сохранить данные.

## 8. Остановка

Дважды кликните `stop.bat` или выполните `docker compose down` в папке
проекта. Контейнеры останавливаются с `stop_grace_period`, воркер
завершает нити камер штатно (закрывает `VideoCapture`/`VideoWriter`,
останавливает ffmpeg-репабликацию) — см. `docs/ARCHITECTURE.md`.

## 9. Устранение неполадок при установке

| Симптом | Причина / решение |
|---|---|
| `[ERROR] Docker Desktop not found` в `start.bat` | Docker Desktop не установлен или не в `PATH`. Переустановите, перезапустите терминал. |
| Docker Desktop не запускается, просит включить виртуализацию | Включите Intel VT-x / AMD-V в BIOS/UEFI. |
| `docker compose up` падает на этапе сборки backend/worker | Нет доступа в интернет (не скачиваются пакеты pip) — проверьте сеть/прокси. |
| Сборка воркера очень долгая (>20 мин) | Первая загрузка модели InsightFace и тяжёлых ML-зависимостей (onnxruntime, opencv) — нормально на медленном интернете; повторные сборки используют кеш слоёв Docker. |
| Backend перезапускается в цикле, в логах "обнаружены секреты по умолчанию" | `.env` содержит публичные значения из репозитория — заполните `SECRET_KEY`/`RTSP_ENCRYPTION_KEY`/`ADMIN_PASSWORD` реальными значениями (см. шаг 4). |
| Камера не подключается | Проверьте RTSP URL (обычно `rtsp://user:pass@ip:554/...` — точный путь зависит от производителя), доступность порта 554 с ПК (`Test-NetConnection <ip> -Port 554` в PowerShell), совместимость субпотока (ТЗ 18.1). |
| Live-просмотр не показывает видео (только снимки) | Камера отдаёт H.265/HEVC — HLS в браузере требует H.264. Переключите поток камеры на H.264 (обычно называется "substream" в веб-интерфейсе камеры). Детекция и архив при этом продолжают работать. |
| Порт 8080/8000/5432/6379/8554/8888/8889 уже занят | Другое приложение слушает порт — задайте свободный порт через переменную окружения в `.env` (например, `POSTGRES_HOST_PORT=5433`, `FRONTEND_HTTP_HOST_PORT=8081` — полный список переменных см. в `.env.example`), без правки `docker-compose.yml`. |
| `docker compose up` падает с `bind: An attempt was made to access a socket in a way forbidden by its access permissions` (обычно Windows) | Порт свободен (не виден ни в `netstat -ano \| findstr :<порт>`, ни в `netsh int ipv4 show excludedportrange protocol=tcp`), но ОС/Docker всё равно отказывает в биндинге — типично для сбойного сетевого стека WSL2 или блокировки антивирусом/firewall. Сначала попробуйте `wsl --shutdown` и перезапуск Docker Desktop; если не помогло — переопределите порт через `.env` (см. строку выше) вместо диагностики ОС. |

Подробнее про логи: `docker compose logs -f backend|worker|frontend` (см.
README). Резервное копирование и восстановление — `docs/BACKUP.md`.
