# e2e — опрос живой системы браузером через настоящий nginx

Сьют отвечает на вопрос, которого не задаёт ни один юнит-тест: **работает
ли функция ТЗ у оператора в браузере**, а не «зелёный ли обработчик».

Между обработчиком и оператором стоят три звена, которых нет в
`backend/tests`: настоящий **nginx** с боевыми `frontend/nginx*.conf`,
собранный бандл фронтенда и сам **браузер** — с его форматами запросов,
куками и WebSocket'ом. Два цикла подряд дефекты находились именно там:

| цикл | что нашлось | чем было невидимо |
|---|---|---|
| 62 | 16 эндпоинтов отвергали штатный `Authorization: Bearer` (422); nginx ходил к бэкенду по HTTP/1.0 без пула | конфиги `nginx*.conf` за 62 цикла ни разу не исполнялись — их сторожили статические тесты по тексту файла |
| 63 | журнал аудита писал `?` вместо имени на **каждом** входе через веб-интерфейс (§10, §14) | все тесты сьюта зовут `/login` через `data=` — urlencoded; браузер шлёт `FormData`, то есть multipart |
| 64 | отчёты §8 и журнал §10 выгружались в CSV без BOM — Excel под Windows показывал кириллицу кракозябрами | раздел «Отчёты» открывался чисто все 63 цикла: **кнопку никто не нажимал**, а проверки читали ответ как текст, где httpx снимает BOM сам |

Все три находки — один класс: **проверка, написанная под то поведение,
которое работает, не проверяет контракт**. Поэтому сьют ходит не «как
удобно тесту», а как ходит браузер, — и с цикла 64 ещё и **нажимает
кнопки**: `test_ui_actions.py` совершает действие, ради которого функция
описана в ТЗ, и смотрит на его результат (скачанные байты, строку в БД,
содержимое после перезагрузки), а не на код ответа.

## Запуск локально

```bash
# 1. Postgres с pgvector, Redis, nginx
sudo apt-get install -y postgresql postgresql-16-pgvector redis-server nginx
sudo service postgresql start && sudo service redis-server start

# 2. Стенд: сборка фронтенда, рендер боевых конфигов nginx, uvicorn
./e2e/run-stack.sh

# 3. Сам опрос
pip install playwright pytest psycopg2-binary redis httpx websockets
python -m playwright install chromium
E2E_BASE_URL=http://127.0.0.1:8080 pytest e2e -q
```

`run-stack.sh` печатает переменные окружения, которые ждёт сьют, и
оставляет стенд поднятым: `./e2e/run-stack.sh --stop` его гасит.

## Что именно проверяется

* **вход как из браузера** — форма уходит `multipart/form-data`, и в
  журнале аудита §10/§14 обязана оказаться учётка, а не заглушка;
* **все 14 разделов интерфейса** открываются без ошибок консоли, без
  необработанных исключений React и без ответов ≥ 400 (§3-§12);
* **живая лента §15** — событие, опубликованное в Redis-канал `faces:new`
  ровно тем payload'ом, что шлёт воркер, доезжает до открытой «Стены
  распознавания» в браузере через `/ws/` за nginx;
* **HLS §4** закрыт `auth_request`: без куки `hls_auth` nginx отвечает 401
  раньше, чем запрос доходит до MediaMTX.

### Действия оператора (`test_ui_actions.py`)

Открытие раздела не значит, что раздел работает. Здесь проверяется само
действие и его последствие:

* **§3** камера заводится **через форму** и переживает перезагрузку списка;
* **§15** полигон зоны рисуется настоящими кликами по `<canvas>` и
  доезжает до колонки `cameras.roi` — с нормированными в 0..1
  координатами (ошибку пересчёта из `getBoundingClientRect()` юнит-тест
  увидеть не может: canvas в нём не существует);
* **§8** отчёты Excel и CSV **скачиваются**, и проверяются их байты: xlsx
  — настоящий zip с листом, csv — с BOM;
* **§10** журнал аудита выгружается ссылкой с токеном в query и тоже
  помечен BOM.

Сьют **не** подменяет `backend/tests`: он не проверяет ветвления логики, а
проверяет, что цепочка «браузер → nginx → бэкенд → Postgres/Redis» цела.
